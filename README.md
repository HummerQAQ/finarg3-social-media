# BAIBAICHUCHU at the NTCIR-19 FinArg-3 Task — Social Media Subtask

Code for the participant paper **"When Is Maximum Possible Profit Predictable
from Investor Text?"** (Team BAIBAICHUCHU, NTCIR-19 FinArg-3, Social Media
Subtask). It covers the submitted three-track system (lexicon LR,
pre-finetuned MacBERT ranker, LLM judge), the post-hoc stance-correction
analysis, and the Section-8 volatility–horizon and margin analyses.

**No task data is included.** The FinArg-3 datasets (training release,
official test pairs, real-time batches, and the 2,100-post July ranking
collection) are distributed by the NTCIR-19 organizers to registered
participants only. Obtain them from the organizers and place them as
described below; every script fails cleanly if its inputs are absent.

## Setup

```bash
python -m venv .venv && . .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
export OPENAI_API_KEY=...                       # only for the LLM-based steps
```

Python 3.11+ is assumed. Scripts that call the OpenAI API (`llm_judge*.py`,
`extract_attributes.py`, `extract_ranking.py`) read the key from the
`OPENAI_API_KEY` environment variable and cache every response on disk, so
reruns are free and deterministic. GPU is optional but recommended for
`prefinetune.py` / `train_encoder.py`.

## Data layout

Place the organizer files (names as distributed) like this:

```
data/                                   # created by you
  <official training release>           # consumed by data_prep.py
  test_pairs.json                       # the 87 official pairs (index/post1/post2)
  test_answer_key.json                  # released answer key, for post-hoc scoring
  fewshot_config.json                   # see "Few-shot exemplars" below
realtime/data/
  FinArg3_Social_Media_Pairwise_<date>.json          # daily real-time batches
  FinArg3_Social_Media_Post_Ranking_2100_Collection.json
```

Everything else under `data/` (fold assignments, pair lists, embeddings,
model scores, price caches, API caches) is generated by the scripts.

## Reproducing the paper, in order

| Step | Script | Paper section |
|---|---|---|
| 1. Normalize the training release, deduplicate, build grouped folds and the 3,591 training pairs | `data_prep.py` | §3, §4.1 |
| 2. Lexicon + n-gram track | `features.py`, `baseline_lr.py` | §4.2, Table 3 |
| 3. Duration pre-finetuning, then the MacBERT ranker (5 seeds) | `prefinetune.py`, `train_encoder.py` | §4.3, Table 3 |
| 4. LLM judge, rubric v3 | `llm_judge.py --mode cv` / `--mode test` | §4.4, Tables 2–4 |
| 5. Attribute extraction + pairwise attribute model | `extract_attributes.py`, `fit_attributes.py` | §3.2 (Table 1), Run 3 |
| 6. Assemble the three submitted runs | `make_submission.py` | §4.5, §6 |
| 7. Real-time week inference | `predict_realtime.py` | §7 |
| 8. Top-210 ranking (extraction, scores, assembly) | `extract_ranking.py`, `score_collection.py`, `build_top210.py` | §7.1 |
| 9. Stance-corrected judge variant (generate, then rerun step 4 with it) | `make_v3sa.py` → `llm_judge_v3sa.py` | §5.4, §6 |
| 10. July price bars with lows | `fetch_ohlc.py` | §8 inputs |
| 11. Shared July sample (TH-MPP construction) | `collection_sample.py` (imported, not run) | §8.1 |
| 12. Volatility–horizon scaling and same-ticker gap statistics | `analyze_scaling.py` | §8.1, §8.3 |
| 13. Pre-posting (ex-ante) volatility experiment, with leakage assertions | `exante_capacity.py`; verify via `tests/test_exante_capacity.py` | §8.2, Table 5-adjacent |
| 14. Text vs. volatility–horizon decomposition | `analyze_crossperiod.py`, `text_capacity_decomposition.py` | §8.5 |
| 15. Stance-definition audit against external prices | `verify_stance_anchors.py` | §3.1 footnote |
| 16. Gap-reliability figure | `plot_gap_reliability.py` | Fig. 1 |

Negative-ablation variants (Table 4) are flags on the same scripts, e.g.
`llm_judge.py --knn`, `train_encoder.py --soft/--margin-weight`,
`prefinetune_rel.py`, `embed_ranker.py`.

Notes on determinism: encoder training uses fixed seeds (42–46); the ex-ante
experiment fixes its bootstrap seed (42) and pre-specifies the 20-day primary
/ 60-day robustness lookbacks in code before any result is computed; LLM
outputs are cached, so published numbers are reproduced exactly from the
caches once populated. Market data come from Yahoo Finance via `yfinance`
(dividend-unadjusted OHLC for outcomes; adjusted closes for pre-posting
volatility), so a re-fetch long after the fact can differ if the vendor
restates history — the analysis scripts truncate to the 2026-07-24 horizon to
keep this surface small.

## Few-shot exemplars

The judge's five few-shot exemplars are real pairs from the official training
release. Because those post texts are restricted, `llm_judge.py` loads them
from `data/fewshot_config.json`:

```json
{"posts": [{"a": "<post text>", "b": "<post text>"}, ...5 items...],
 "exclude_snippets": ["<distinctive substring of each exemplar post>", ...]}
```

The rationales, labels, and confidences are in the script; only the post
texts are external. Registered FinArg-3 participants can request the exact
config (or the pid list to rebuild it) from the authors.
